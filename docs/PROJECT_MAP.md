# Project Map

> В этой копии приложения доступны исходники и Gradle-сборка `stagingDebug`. Для бета-сборки потребуется собственный `app/src/beta/google-services.json`. Шаблон CI хранится в `docs/examples/beta-distribution.yml.example` и запускается после настройки в своём репозитории. Из архива дизайна исключены скриншоты с данными пользователей и рабочих запросов.

This file is the current map of the Android project. Update it after every meaningful code change that adds, removes, moves, or materially changes project files or implemented feature status.

## Project overview

`ysukampus` is a single-module Android app (`:app`) built with Kotlin, Jetpack Compose, Material 3, Retrofit, OkHttp, and kotlinx.serialization.

The current app entry point is `MainActivity`, which applies `YsukampusTheme` and launches `RegistrationFlowScreen`. The retained auth flow restores session state, starts either dev or Telegram authorization, and then routes the authorized user into the same `MainScreen` shell with footer tabs; the existing `AdminPanelScreen` opens from that shell and returns back through its header home button.

## Current launcher path

```text
MainActivity
└─ YsukampusTheme
   └─ RegistrationFlowScreen
      ├─ CheckingSession
      ├─ DevLoginScreen / Telegram auth states
      ├─ MainScreen
      └─ AdminPanelScreen -> back to MainScreen
```

## Admin implementation notes

- Admin UI is currently Compose-only and root tab/search/dialog state is wired through `AdminViewModel`.

- Authorized/admin Retrofit clients and the registration root now share one `SessionManager`; when refresh/auth retries still end with `401 Unauthorized`, tokens are cleared and `RegistrationFlowScreen` sends the user back to registration instead of leaving the failure only in admin feedback.
- `docs/ADMIN_BACKEND_CONTRACT_CHECKLIST.md` was manually verified before enabling `RemoteAdminRepository`.
- Role/permission dialog create/update/delete/restore buttons are wired to payload-based ViewModel events.
- User-role and role-permission assignment UI controls are wired to ID-based ViewModel events with local selection validation.
- Add-role dialog can collect initial permissions locally; `AdminViewModel` assigns them after `createRole` returns the new role id.
- History/changelog support is wired through models, DTOs, API, mappers, repositories, `AdminUiState`, `AdminEvent`, `AdminViewModel`, the History tab list, records dialog, and record detail dialog; records dialog sorts entries newest-first by change date.

- Loading, error, success/message, saving/deleting, and filtered empty states are visible in the admin UI.

- Launcher is currently `RegistrationFlowScreen`; unauthenticated users authorize first, then tap "Открыть админ панель" to reach admin/backend calls.
- Build-type app names are configured through `manifestPlaceholders["appName"]`: `ysukampus debug` for `debug`, `ysukampus beta` for Firebase `beta`, and `ysukampus` for `release`.
