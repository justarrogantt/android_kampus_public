# Project Map

> В этой копии приложения доступны исходники и Gradle-сборка `stagingDebug`. Для бета-сборки потребуется собственный `app/src/beta/google-services.json`. Шаблон CI хранится в `docs/examples/beta-distribution.yml.example` и запускается после настройки в своём репозитории. Из архива дизайна исключены скриншоты с данными пользователей и рабочих запросов.

This file is the current map of the Android project. Update it after every meaningful code change that adds, removes, moves, or materially changes project files or implemented feature status.

## Project overview

`ysukampus` is a single-module Android app (`:app`) built with Kotlin, Jetpack Compose, Material 3, Retrofit, OkHttp, and kotlinx.serialization.

The current app entry point is `MainActivity`, which applies `YsukampusTheme` and launches `RegistrationFlowScreen`. The retained auth flow restores session state, starts either dev or Telegram authorization, and then routes the authorized user into the same `MainScreen` shell with footer tabs; the existing `AdminPanelScreen` opens from that shell and returns back through its header home button.

## Current launcher path

```text
MainActivity
└─ YsukampusTheme
   └─ RegistrationFlowScreen
      ├─ CheckingSession
      ├─ DevLoginScreen / Telegram auth states
      ├─ MainScreen
      └─ AdminPanelScreen -> back to MainScreen
```

| WebSocket token expiry handling | Implemented | Catch-up phase 1 is done. `app/routers/ws.py::reject()` accepts the socket before `close(1008)`, so the real policy-violation code reaches the client. `BaseWebSocketClient` treats close code `1008` (and HTTP 401/403 on the handshake) as a rejected token: before the next backoff attempt it refreshes the access token through the shared `TokenRefresher` and reconnects with the new one. A failed refresh reports through `SessionManager::onNotAuthorized` and stops reconnecting; two rejections in a row after a successful refresh also stop the socket, but without touching the session — on the moderator channel that case means missing `moderate-forum` permission, not an expired token. |
| Live moderation queue counter | Implemented | `ModeratorWsEvent.ModerationCount` parses `{"type": "moderation_count", "count": N}` and `AdminViewModel` writes it into `AdminUiState.moderationQueueCount`, which renders as the `В очереди: N` chip above the moderation search field. The backend pushes it on every queue change (`forum_service.broadcast_moderation_count`) and not on connect, so the chip appears only after the first change. |

## Admin implementation notes

- Admin UI is currently Compose-only and root tab/search/dialog state is wired through `AdminViewModel`.
- Dialog form fields are still local inside dialog composables for now; role/permission save actions trim local form values before converting them into `AdminRoleInput`/`AdminPermissionInput`.
- `AdminViewModel` receives `AdminRepository` from `AdminViewModelFactory`; `AdminRepositoryProvider` supplies `FakeAdminRepository` by default and `RemoteAdminRepository` when `Remote` is explicitly selected.
- `AdminPanelScreen` currently selects `AdminDataSourceMode.Remote` after successful backend smoke testing, and it is opened from the authorized registration screen.
- Prepared admin DTOs, `AdminApi`, mappers, `createAdminApi`, and `RemoteAdminRepository` are active for backend-backed admin data.
- Authorized/admin Retrofit clients and the registration root now share one `SessionManager`; when refresh/auth retries still end with `401 Unauthorized`, tokens are cleared and `RegistrationFlowScreen` sends the user back to registration instead of leaving the failure only in admin feedback.
- `docs/ADMIN_BACKEND_CONTRACT_CHECKLIST.md` was manually verified before enabling `RemoteAdminRepository`.
- Role/permission dialog create/update/delete/restore buttons are wired to payload-based ViewModel events.
- User-role and role-permission assignment UI controls are wired to ID-based ViewModel events with local selection validation.
- Add-role dialog can collect initial permissions locally; `AdminViewModel` assigns them after `createRole` returns the new role id.
- History/changelog support is wired through models, DTOs, API, mappers, repositories, `AdminUiState`, `AdminEvent`, `AdminViewModel`, the History tab list, records dialog, and record detail dialog; records dialog sorts entries newest-first by change date.
- Request-log support is prepared in DTO/API/mappers/repositories; request-log UI wiring is still TODO.
- Task 18 added request-log state/events/ViewModel flows and placeholder screen/dialog branches.
- Task 19 completed: final Logging tab list UI.
- Task 20 completed: request-log filter dialog UI.
- Task 21 completed: request-log details dialog UI + delete action wiring.
- Loading, error, success/message, saving/deleting, and filtered empty states are visible in the admin UI.
- Backend integration is active through `AdminDataSourceMode.Remote`; switch to `AdminDataSourceMode.Fake` only for local UI development or fallback testing.
- Launcher is currently `RegistrationFlowScreen`; unauthenticated users authorize first, then tap "Открыть админ панель" to reach admin/backend calls.
- Build-type app names are configured through `manifestPlaceholders["appName"]`: `ysukampus debug` for `debug`, `ysukampus beta` for Firebase `beta`, and `ysukampus` for `release`.
- Firebase `google-services` processing is intentionally enabled only for the `beta` build type; local `debug` builds do not require `google-services.json`.
- Registration polling logs auth failures to Logcat and surfaces endpoint-specific backend errors such as `POST auth/code/confirm/{code} вернул HTTP 500: ...`.
- Product flavors split auth entry points: `dev` uses backend `POST /api/auth/dev/login`, while `staging` keeps Telegram code generation, polling, and confirmation.
- Retrofit deserialization intentionally ignores unknown JSON keys; additive backend fields should not crash the mobile client even before DTO cleanup lands everywhere.
- Keep previews independent from networking.
- When adding admin logic later, keep composables rendering state and emitting events; place data operations outside composables.
- Next TODO: continue backend hardening around confirmed backend edge cases while keeping `FakeAdminRepository` available for local UI-only work.
